# ЛР1. Реалізація та перевірка зворотного поширення похибки

Мережа: X -> Linear(4, 8) -> ReLU -> Linear(8, 3), дані Iris, float64.
Python 3.12, NumPy 2.5.3, PyTorch 2.14.1, scikit-learn 1.9.1 (лише для load_iris).

## Запуск

```
cd lab1
uv sync --frozen
uv run python run_all.py
uv run python run_all.py --bug
uv run python experiment_bug.py
uv run python test_stability.py
```

За замовчуванням працює правильна реалізація. run_all.py повертає код 0, якщо всі перевірки пройдено.
З прапорцем --bug код 0 означає, що помилку виявлено.

## Дані та ініціалізація

Поділ: rng = np.random.default_rng(0), класи 0, 1, 2 по черзі, індекси кожного класу перемішуються,
перші 35 йдуть у навчальну вибірку, решта 15 у тестову (105 і 45 об'єктів).
Стандартизація: середнє і стандартне відхилення (ddof=0) лише за навчальною вибіркою.

Ініціалізація (новий default_rng(0), спочатку W1, потім W2):
W1 ~ N(0, std = sqrt(2/4)), W2 ~ N(0, std = sqrt(2/(8+3))), b1 = 0, b2 = 0.

## Формули та розмірності

N число об'єктів (у перевірках N = 105). Ваги мають форму (in, out).

Прямий прохід:

| Величина | Формула | Форма |
|---|---|---|
| X | вхід | (N, 4) |
| Z1 | X W1 + b1 | (N, 8) |
| A1 | max(0, Z1) | (N, 8) |
| Z2 | A1 W2 + b2 (логіти) | (N, 3) |
| L | (1/N) sum_i [ -log softmax(Z2_i)[y_i] ] | скаляр |

Стабільна крос-ентропія. Нехай m = max_j z_j, тоді
log softmax(z)_k = (z_k - m) - log sum_j exp(z_j - m).
Усі показники експонент не перевищують нуля, а доданок для максимального логіта дорівнює 1,
тому сума не переповнюється і не дорівнює нулю. Для логітів [1000, 1001, 1002] наївна формула дає nan,
стабільна дає скінченне значення, яке збігається з torch.nn.functional.cross_entropy до 1e-12.
Приклад з лекції ([90, 91, 92], клас 2) дає 0.4076.

Зворотний прохід (P = softmax(Z2), Y = one-hot міток):

| Градієнт | Формула | Форма |
|---|---|---|
| dZ2 | (P - Y) / N | (N, 3) |
| dW2 | A1^T dZ2 | (8, 3) |
| db2 | сума dZ2 за віссю об'єктів | (3,) |
| dA1 | dZ2 W2^T | (N, 8) |
| dZ1 | dA1 * 1[Z1 > 0] | (N, 8) |
| dW1 | X^T dZ1 | (4, 8) |
| db1 | сума dZ1 за віссю об'єктів | (8,) |

Вивід. Для softmax з NLL похідна за логітами одного об'єкта дорівнює p - onehot(y).
Усереднення втрати за об'єктами додає множник 1/N. Далі ланцюгове правило: з Z2 = A1 W2 + b2 випливає
dW2 = A1^T dZ2 і dA1 = dZ2 W2^T. Якобіан ReLU діагональний, diag(1[Z1 > 0]), у нулі похідна 0 (як у PyTorch).
З Z1 = X W1 + b1 випливає dW1 = X^T dZ1.

## Збережені проміжні значення

Після прямого проходу в cache зберігаються:

- X (N, 4): потрібен для dW1 = X^T dZ1
- Z1 (N, 8): потрібен для маски ReLU, Z1 > 0
- A1 (N, 8): потрібен для dW2 = A1^T dZ2
- Z2 (N, 3): з нього через log-softmax відновлюється softmax для dZ2

Матриця W2 береться з параметрів для dA1 = dZ2 W2^T. Пам'ять під ці значення зростає лінійно з N.

## Звірка з PyTorch

Критерій: |a - b| не більше 1e-12, усі значення скінченні. Для градієнтів береться максимум за всіма елементами.

Втрата NumPy:   1.456200780114282
Втрата PyTorch: 1.456200780114282

|---|---|---|

| Градієнт W1 | 5.551e-17 | так |

## Чисельна перевірка

Центральна різниця g_num = (L+ - L-) / (2 eps), eps = 1e-6, початкові ваги, повна навчальна вибірка (105 об'єктів).
Критерій: |g_num - g_manual| не більше 1e-7.

## Дослід із навмисною помилкою

У градієнті за логітами пропущено ділення на N, функція втрат не змінювалась (backward з divide_by_n=False).
Ті самі початкові параметри і ті самі 105 об'єктів, ваги не оновлювались.

Прогноз, записаний перед запуском:

1. Втрата не зміниться: помилка лише в backward, а прямий прохід і функція втрат не змінювались.
2. Усі ненульові градієнти зростуть у N = 105 разів: dZ2 множиться на 105, а всі градієнти лінійні за dZ2.
3. Помилку виявлять обидві перевірки градієнтів. З PyTorch різниця буде порядку (N - 1) |g| замість 1e-12,
   з чисельною похідною так само, бо центральна різниця дає справжній градієнт. Порівняння самих значень втрати помилку не виявить.

## Висновки

- Ручний backward збігається з PyTorch autograd до близько 1e-16 і з чисельним диференціюванням до близько 1e-10,
  що значно краще за допуски 1e-12 і 1e-7.
- Перевірки доповнюють одна одну: autograd це незалежна реалізація, а центральна різниця не залежить від виведених формул.
- Збіг значення втрати не гарантує правильних градієнтів: у досліді втрата збіглася, а градієнти були хибні.
- Зсув на максимум робить крос-ентропію стійкою там, де наївний softmax дає nan.
- Ваги NumPy мають форму (in, out), а torch.nn.Linear зберігає (out, in), тому при копіюванні їх транспонують.
